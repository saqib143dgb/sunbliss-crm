# CRM development requirements

The application has live and isolated Test Mode workspaces. Read TEST_MODE.md
before changing database schema, authentication, network clients, document export,
workflow RPCs, storage or external integrations. Keep both modes functional in the
same release. A change must never make Test Mode fall back to production data.

## Shared project engine
Triana is generated by scripts/build-project-workspaces.js from the finished
Sunbliss build, including all post-build UI changes. Never maintain a separate
Triana screen implementation. Project identity and verified settings may differ.
Triana data lives in crm_triana and its test data in crm_triana_test. Keep both
schemas aligned with public table shape in every future schema release. Their
private refresh_workflows functions synchronize compatible shared routines on
workspace entry and fail closed on drift. No fallback to public business data.
Do not copy Sunbliss bank details, SPA legal templates, customer rows or unit
inventory into Triana. The shared SPA editor remains blocked until an approved
Triana template is configured and its page mapping is validated.
